## 一、最重要的目标

整段产品展示只有一套持续存在的工作台。旁边的标题、说明与少量操作随章节变化；工作台留在原位置，内部在不同形态之间连续切换。

完整主线：纸片总览 → 胶囊与预览 → Markdown → 脚本 → Codex 制作插件 → 回到桌面，新插件与原有纸片一起出现。

当前版本只让前三章共用 `#desktop-scene`，脚本另用 `.script-stage`，插件另有 `.studio` 和 `#tool-canvas`。本轮把它们整合进同一个舞台和同一套持久状态。生成结果进入原工作台，而不是插件区下面新增的另一块画布，也不是滚动回顶部模拟返回。

## 二、工作台怎样变化

| 旁边正在讲什么 | 同一工作台中的变化 |
| --- | --- |
| 纸片与待办 | 展示固定待办纸和笔记纸，可勾选少量预设待办。 |
| 待办关联笔记 | 一项待办预先关联那张笔记，点击关联入口即可打开或聚焦对应笔记。 |
| 胶囊 | 同一组纸片收至边缘；可预览、勾选和重新展开，状态与完整纸片一致。 |
| Markdown | 同一张笔记展开到适合阅读的尺寸，按 PaperTodo 4.0 实际档位展示效果。 |
| 脚本 | 工作台中调入预设脚本纸，演示笔记→闪电胶囊→结果→返回；保留与原桌面的空间联系。 |
| Codex 制作插件 | 同一工作台进入制作形态，展示描述需求、制作过程和结果；原纸片可退到边缘，为制作区腾出空间。 |
| 制作完成 | 收回制作区，恢复原来的桌面形态，新插件出现在预留位置，与待办、笔记共同存在。 |

工作台外框与位置保持稳定。允许内部重排、纸片展开、折叠和聚焦；尽量用已有对象的连续变化解释功能。用户回看前一章节时，已经生成的插件、勾选和其他必要状态仍然存在。

## 三、精简操作，控制展示范围

这是有明确内容安排的产品演示。每个开放的操作都要帮助理解一个真实能力。

- 初始只放固定待办与固定笔记。脚本按章节出现，插件最多占用一个演示位置。
- 去掉面向访客的自由新建待办／笔记、无限复制、多份插件堆叠和任意删除入口。已有内部创建逻辑可以继续服务章节展示。
- 再次制作插件时更新那个预留位置；不不断新增窗口，旧实例及时释放其计时等活动。
- 待办与笔记提前关联好。用户只需点开关联笔记，不需要选择绑定对象、拖拽创建关系或学习关联流程。
- 第三方窗口绑定是另一个功能，不在网页中伪造绑定外部应用的体验。
- 优先保留待办勾选、打开关联笔记、收起／展开、胶囊预览、Markdown 对照，以及生成后的计时器等核心操作。
- 拖动、自由编辑、置顶等操作只在确实服务当前展示时保留；不因复用旧组件而默认开放整套操作面板。
- 未提供的演示能力不做成可点的假按钮，避免点击后只弹出“网页不支持”的说明。说明应简短、就近。
- 网站专用的模式切换和章节控制放在讲解侧；产品内部按钮的位置、含义与结果按当前桌面程序核对。

## 四、4.0 界面与新版视觉

沿用当前融合版的浅纸色、鼠尾草绿、深色文字、少量荧光绿强调和清晰留白。重点调整结构与交互，保留已经可用的视觉基础。

待办行、笔记、工具栏、胶囊和预览卡应对齐最新版 PaperTodo 4.0。用当前源码、资源和可信实机材料核对，不把旧官网 2.x／3.x 演示当成产品事实。网页可以为讲解精简操作，但剩余操作必须符合真实语义。

当前材料中的原生 UI 主要来自源码核对，未完成全部实机外观验证。缺少依据的部分如实列出；不把设计推断声称为实机验证结果。

## 五、Codex 制作流程的展示边界

制作段要表达“通过 Codex 把一个需求做成插件，再放回 PaperTodo 桌面”的完整过程。重点在制作形态与桌面形态的连续衔接。

当前基线只使用三个本地模板。如果这一轮继续采用模拟，应在制作区域用一处清楚的短提示说明“流程演示／本地预设，未实时调用 Codex”，并明确网页展示结果与真实桌面插件的区别。不要把模板拼装标成真实模型调用；也不要在每一处反复堆叠技术免责声明。

本轮不要求增加 API 后台、密钥输入或真实 Windows 安装能力。已有源码／导出等次要功能可以收进不抢占主线的位置。

## 六、桌面、手机与阅读

- 桌面端让工作台持续留在讲解内容旁边，滚动或点击章节都能切换展示形态。普通滚动不应被锁死，输入控件不被页面快捷键抢占。
- 修正目前“高度低于约 760px 就隐藏共享工作台”的处理。宽桌面的小高度窗口仍应尽量保留并列结构，通过合理缩放、压缩次要间距或内部滚动保证可用。
- 真正窄屏时，把同一工作台与当前讲解合理上下组织，继续共用状态；避免复制多套互相独立的桌面造成重复和混乱。
- 兼顾中英文、长文本、触屏点击、键盘焦点和减少动画偏好。界面切换不能丢失当前演示成果。

## 七、交付和验收

直接交付可运行改版，不只输出设计建议。保留静态网站、相对资源路径和简单 HTTP 预览方式。

重点验收：

1. 从纸片到脚本、制作插件、回到桌面，整条主线使用同一工作台，其他区域只承担讲解与必要控制。
2. 点击预设待办的关联入口，打开的是原来的那张笔记；无需建立绑定。
3. 生成一个插件后，原待办、笔记和新插件同处原工作台；回到胶囊章节，新插件仍在，可参与合理的收起／展开演示。
4. 再次生成只替换唯一插件位置；不增加新的画布或无穷纸片。
5. 1440×900、1366×768、1280×720 及 390px 手机宽度下，主要内容可读、操作可达，中英文没有意外横向溢出。
6. 通过真实 HTTP 页面验证模块加载和上述流程；更新与新交互约束有关的现有测试。分别列出实际通过的检查与尚未验证的内容。

交付源码、可直接查看的预览、关键截图和简短验证结果。只修改实验分支，不合并主线、不发布正式官网。若当前环境不能写 GitHub，交付完整源码替换包及预览文件，说明没有更新远端。
