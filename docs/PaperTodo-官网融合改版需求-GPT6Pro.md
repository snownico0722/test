## 2. 三部分如何融合

**旧站负责体验结构。** 保留“滚动阅读讲解，同时操作旁边的产品演示”的主线。桌面端先是纸片总览，接着讲胶囊，再进入 Markdown；同一个固定演示区随章节切换状态。后面继续展示脚本、扩展能力、特性、FAQ 和下载。

**Playground 负责网站视觉。** 采用它的浅纸色、鼠尾草绿、深绿色文字、少量荧光绿强调、清晰留白，以及无衬线与衬线标题的组合。导航、标题、按钮、功能区和交互舞台应形成统一的设计。

**最新版桌面程序负责产品演示的依据。** 重新核对待办纸、笔记纸、工具栏、胶囊、预览卡和 Markdown 的结构及状态。演示区可以做适合网页的比例调整，但核心控件含义、操作位置关系和结果要能与实际软件对应。

最终应是一套连续、完整的新官网。主要功能在首页即可体验，旧站链接只作为参考或归档入口。首页每个章节、每个演示组件都应完成改版，包括纸片内部与展开后的状态。

## 5. 视觉规范

沿用 Playground 的设计方向，下面的颜色可作为起点；对比度与整体一致性优先：

| 用途 | 参考值 |
| --- | --- |
| 页面背景 | `#F5F4ED` |
| 纸片底色 | `#FFFDF3` |
| 主要文字 | `#242B25` |
| 次要文字 | `#667064` |
| 细分隔线 | `#D7DBCF` |
| 强调色 | `#DCF58C`，少量使用 |
| 深色面板 | `#222C25` |

网站标题采用有层次的无衬线／衬线组合，中文单独调校字重、行高和断行。正文以约 15–17px 的阅读尺度设计；演示内部主要内容也要清晰可读。小字只用于次要提示。

统一圆角、边框、阴影、按钮、标签、模式切换器、提示与焦点状态。用克制的纸张层次和轻阴影增加质感；纹理和装饰作为背景。新的外层页面与演示内部在间距、色彩和线条上保持衔接，同时保留桌面产品的识别特征。

软件配色切换应反映当前实际主题。页面品牌配色与软件主题是两个层级，软件的浅色／深色状态需要覆盖纸片、文字、工具栏和胶囊。

## 6. 交互与状态要求

请先列出旧站交互清单，再逐项迁移。下面是最低要求：

- 保留桌面端固定演示区随总览、胶囊、Markdown 章节联动的结构，章节切换有连续感。
- 待办勾选、单张纸片折叠与展开、主胶囊队列收起与展开、配色、深浅色、Markdown 手动切换、脚本演示、FAQ、语言和锚点导航均正常。
- 进入 Markdown 章节时，笔记平顺过渡到适合阅读的尺寸；退出时恢复合理状态，用户的折叠状态与输入内容有明确处理。
- 自动演示用于帮助理解，用户操作后应让出控制。页面隐藏或对应章节离开视口时停止相关自动演示；支持减少动画偏好。
- 用户在当前会话中的勾选、编辑内容和选择不因切换语言或普通章节滚动而意外丢失。需要重置时提供明确入口。
- 可以复用 Playground 已有的纸片拖动、编辑、新增和整理能力。拖动的触发区域、边界及与滚动的关系必须明确；输入框和按钮保持正常操作。
- 滚动分段保留旧站的阅读节奏，同时处理触控板、反向滚动、长内容和内部滚动区。手机、小高度窗口和放大页面以内容可完整阅读为准。
- 折叠动画的目标应是当前胶囊的位置；在调整窗口尺寸、移动纸片和切换章节后仍然对应正确。
- 脚本区使用浏览器内的演示结果，可重播和返回。网页演示不执行用户电脑上的 PowerShell。
- 可点击控件应有实际行为和反馈。未支持的操作明确说明，装饰图标保持装饰用途。

动画可以重新设计时长和节奏，重点是纸片与胶囊的对应关系、状态切换清楚、连续操作稳定。避免章节转换引起大面积布局跳变。

## 8. 移动端与双语

手机端重新组织演示的位置和尺寸，保留待办、胶囊、Markdown、脚本、扩展、六项特性、五项 FAQ 和下载信息。结合 9:18–9:21 长屏比例安排足够可读的真实内容，让演示面板充分使用纵向空间。
